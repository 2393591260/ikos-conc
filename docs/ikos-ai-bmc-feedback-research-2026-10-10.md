不是已有实验贡献、创新性认证或论文录用预测。

默认基线TP106/TN661/UNKNOWN261/FP0/FN0/error1。方案A的独立覆盖查询已实现并通过
双ABI定向与默认全量验证，启用配置的消融仍在进行；方案B尚未提交，C尚未实施。
可消费事实的局部合同见§9及优化计划§9.32，不默认整个AI已经获得普遍soundness证明。

近期优化计划§9.25–26用原生地址/CFG充分条件恢复4个TN，并用独立BV查询核对重叠引理；
这是可复用的事实来源和原型对照，**不是本篇方案A已经实现，更不是BMC反向反馈的贡献证据**。

不能把现有4个TN重新归因于尚未实现的反馈。参考工具的helper解锁误判与ILP32布局分歧
也要求按具体合同核对，不能用参考TRUE或有界PASS认证AI事实。

**可以让 BMC/SMT 反过来辅助 IKOS 抽象解释，但需要两种不同的查询契约。**
有限真实执行搜索可发现竞争并提供优化线索；若要反向增加 SAFE/TN，
必须用覆盖所有相关状态/转移的约束证明候选不可能冲突，或证明精化后的不变式归纳闭合。
当前两前缀 BMC 的有界 UNSAT 不具备这种证明能力。

最适合先试验的路线是：**稳定 AI over-approx → 按需 SMT 候选排除 → 查询结果指导分区/变量 packs → AI 重新收敛并验证**。
并发归纳摘要认证作为后续扩展，不建议先将其承诺为第一篇论文必做大系统。

## 1. 当前系统提供了什么真实基础

### 1.1 已有 AI→BMC 信息流

当前 [BMC complete §3.1](ikos-bmc-complete.md#architecture) 记录了：
may-points-to、offset/width、实际创建前缀、AR/DataLayout 初始化、局部 no-wrap 证书等。
这些为候选选择、值/地址定义性和公式构造提供接口，说明不是从零实现另一套 C 分析器。

但实际收益必须消融证明：历史 TP35 阶段观测到 bounds 256 次/49 任务、SC 来源 648 次/43 任务，
不等于加速已成立；后来对选出的 21 个恢复任务关闭 bounds/no-wrap，TP 仍 21→21。
这只说明那次结果消融未减少 TP，不证明时间、内存无收益，也不证明新方案一定有收益。
本轮未重新做这些旧实验。

已有 `CandidateFacts`、`facts.hpp`、`AccessRecord`、动态实例/AR 执行导出和离线执行检查可复用，
原审查在AI摘要中发现过FN，修复情况见优化计划§9；不得直接把所有候选bounds作为反向SAFE的可信假设。
先封堵已知错误前提，再为每种可消费事实规定作用点、owner、近似方向、版本和有效性。

### 1.2 BMC 已有能力及不能直接复用的部分

已有受限 SC 读来源、机器整数、地址/width、动态创建/call/loop 身份和真实同步，
可以在所选范围内搜索并检查有限竞争执行。
离线 AR 检查已对历史 106 个标签 TP 的 132 组所选执行 ACCEPT；
这仍是受前端/快照/API 合同约束的执行证据，**不是完整 C 或全部 SAFE 的证明**。

`check_race` 的路径选择、展开界、unsupported gate 和存在性约束服务于 FALSE。
SAFE/归纳查询需要不同入口和覆盖义务，不能把 `BOUNDED_UNSAT` 改名当证书。
实现时可复用 solver context、位宽/地址表达式等已有组件；
只有确实共享代码时才抽表达式构造，避免为论文先重写全部 BMC。

## 2. 必须区分的三类查询

| 查询 | 公式覆盖/近似 | SAT 意义 | UNSAT 意义 |
| --- | --- | --- | --- |
| 当前有界竞争 BMC | 所选有限路径/前缀，值/同步必须对应真实执行 | 经执行检查后可确认竞争 | 这些搜索范围没有反例；不是 unbounded SAFE |
| AI 事实下的候选不可冲突查询 | 包含所有相关具体访问状态、可能对象/地址及 width 的 over-approx | 可能冲突，可能抽象伪报；不能确认 TP | 若覆盖前提成立，该候选冲突被排除 |
| 不变式/摘要归纳检查 | 初始状态与所有相关本地/环境步的 over-approx | 存在闭包漏洞，可能抽象伪路径；用于修正摘要 | 结合初值、结构覆盖及全局闭合，可认证该不变式 |

自由变量在 FALSE 公式中可能产生假执行；
在第二/三种查询中，用它扩大允许状态往往是保守的，会降低证明能力。
近似方向必须随查询目的明确，不能用一个通用“SMT 返回真假”接口混用语义。
超时/未知均退 UNKNOWN 或保留原 may 候选。

## 3. 方案 A：AI over-approx 支持的按需候选排除

### 3.1 为什么可行

抽象解释的过近似意味着所有真实候选状态都包含在抽象约束集合 A 中。
如果 `A ∧ conflict` 无解，那么真实状态中也不存在这类冲突。
这是包含性加 UNSAT 的直接推理，不需要限定循环执行次数。

形式化地，若相关具体访问对状态集合 S 满足 `S ⊆ γ(A)`，
且 C 的编码覆盖所有具体冲突，则：

```text
UNSAT(A ∧ C)  ⇒  不存在 s∈S 发生该候选冲突。
```

关键难点是 `S ⊆ γ(A)` 与 C 的覆盖，不是 solver 调用。
A 可以是两个访问点的局部不变式投影的笛卡尔积：该积较粗，但覆盖所有真正共同执行状态。
若添加跨线程等式、同步或关系，必须另有证明，不能因为变量名相同就共享一个局部符号。

### 3.2 可检查的例子：偶/奇元素访问

同一 `int data[16]` 对象，假设 ABI `sizeof(int)=4`，有效范围和无 wrap 已证明：

```c
/* A */ data[2*i]     = ...; /* 0 <= i < 8 */
/* B */ data[2*j + 1] = ...; /* 0 <= j < 8 */
```

区间起点的独立 hull 可以重叠，无法凭普通区间排除。
保留仿射表达式后，字节区间分别是 `[8*i, 8*i+4)` 与 `[8*j+4, 8*j+8)`。
整数约束下两者永不重叠，可用 SMT 证明；i、j 不需要来自同一线程或保持相等。

IKOS 现有 `symbolic_byte_offset` 能表示单变量仿射项，`AccessRecord` 已携带 width，
类型域/局部范围可提供初步事实；这些是实现落点。
但当前接口能否为每个动态访问保留完整来源、溢出和有效地址证明需要原型核实。
**本轮没有实现该例，也没有测得 TN 增量。**

必须有的反向对照：两边都访问偶数；引入可重叠混合 width；不明 base/offset；
允许 wrap 的机器下标；不同线程同名局部；共享 load 决定下标。
未证明真实范围时省略约束扩大 A，若仍可证 UNSAT 才可排除。

### 3.3 IKOS 落点与安全边界

在 checker 已有 may 对中挑出区间不能判定、但表达式/类型来源可完整转换的少量候选。
单独加入 `PairExclusionResult` 之类的类型化结果，内容至少包括：
候选身份、使用的 AI facts/版本、对象/地址/width 合同、公式或可重查摘要、UNSAT 状态。
这不是竞争 witness，也不应混入 FALSE 的 `confirmed_pair_id`。

- unknown alias/TOP 不能直接删除，需纳入全部可能对象或放弃查询。
- 所有重叠字节都必须覆盖，不能复用只比较起始地址的关系。
- 候选 UNSAT 只删除该对；程序 SAFE 仍需要全部访问覆盖、全部候选有充分排除依据且分析完整。
- 如果 A 包含不可靠/过时的共享区间，局部 UNSAT 可能错。事实失效必须撤回排除结果并重算。
- 只纳入独立证明的 definedness 前提，不用未证无溢出/不逃逸假设缩小状态集。

有限候选优先级、预算和缓存可以改善成本；预算耗尽保留 may，不改变结论方向。
可先仅支持完整可转换的局部数值/仿射地址，未知共享值保持自由过近似。

## 4. 方案 B：模型与查询指导 AI 精化

### 4.1 可做什么

BMC 的真实竞争执行、候选排除查询的抽象 SAT 模型、归纳检查的失败模型，可以分别提示：

- guard 合流丢失了哪些分支，是否对这些谓词做 trace partitioning；
- 哪些变量关系需要在同一 pack 中保留；
- 哪个 widening cell 过早变 TOP，是否值得按已证明有效阈值重算；
- 哪个创建/句柄上下文被合并，是否值得细分动态身份；
- 哪些干扰来源/对象字段应该分区，避免无关数据污染。

这些模型的证据强弱不同，必须保留来源。
真实竞争说明至少一个坏执行；抽象 SAT 只说明当前证明不足；
归纳失败模型说明拟议摘要还不闭合，不必是真实整程序执行。

### 4.2 为什么不能直接把模型当不变式

有限轨迹观察到 `x∈{0,1}` 不能证明所有执行都满足这个范围；
本轮 F6 就说明舍弃一个可能写值会错误消除分支。
BMC 搜索没有看到一个线程/写值，也不能推出它不存在。

安全用法是 **模型建议配置，AI 重新求覆盖不动点**：
分成 P 和 ¬P 两个穷尽分区，保留两边的并集；
切换关系域/packing 时保持正确抽象转移；扩大上下文后覆盖全部创建；
调整 widening/narrowing 后验证 postsolution。
模型不能给权限从已有不变式删掉未见过的状态。

一种轻量原型可只记录“哪条候选相关关系丢失”，生成第二轮 AI 的 packing/partition 参数。
这能先验证工程收益；没有独立归纳检查时，SAFE 仍依赖 AI 的正确转移/收敛契约，
不能包装成 solver 认证的安全结论。

### 4.3 循环反馈的终止与成本

每个任务限定精化轮数、分区数量、新增 pack/实例数和累计求解预算。
无收益、solver unknown、上下文爆炸时退回原保守结果，保留尝试记录。
缓存按源/AR 版本、摘要版本、机器模型及查询契约区分。
要证明精化后的 AI 更有信息或更省成本，而不是增加了第二轮完整分析却没有判定改善。

## 5. 方案 C：带归纳检查的并发摘要

这是更强、也更难的研究方向。Miné 的干扰不动点与 Goblint local-trace 约束系统
提供了如何汇总环境效果的理论依据，但当前 BMC 编码不能直接成为完整检查器。

### 5.1 最小证明义务

对候选不变式 I、初始集合 Init 和覆盖语义的转移 `T_over`，至少检查：

```text
Init ∧ ¬I                         UNSAT  // 初始包含
I ∧ T_over ∧ ¬I'                  UNSAT  // 对全部相关一步转移闭合
I ∧ Bad                           UNSAT  // 安全性质
```

并发场景的 `T_over` 必须包含线程本地步及所有允许环境干扰，
处理 lock/unlock、线程创建/join、对象发布和需要支持的 API。
归纳摘要可以忽略精确时间顺序以扩大状态；不能漏掉环境步。
函数/cycle 切点若覆盖完整区域，其无界证明来自切点闭包/归纳，而非某个固定展开次数。

### 5.2 避免 rely/guarantee 循环自证

先用可信保守环境 R_old 检查精化候选，或给整组局部保证/环境摘要建立同时归纳证明：
初始状态成立，各线程在获准环境下保持不变式，所有可能输出效果都纳入其他线程依赖的环境。
不能先假定精化 R_new、删除不利写，再仅在这个 R_new 下“证明”自己。

保护/私有摘要也属于条件化断言，如“持真实 mutex m 且对象未发布时关系成立”，
而不是全时刻可用等式。Goblint `basePriv.ml` 的 `invariant_global` 会用 ghost locked 条件处理保护前提，
这是有实际代码依据的设计提醒，不是把多个保护事实无条件相与。

摘要的依赖/版本改变时重查；API 不支持、初始包含失败、求解器超时都保留原 over-approx 或 UNKNOWN。
对后续动态 heap/弱内存/任意 extern 扩展，需要额外覆盖论证，不能先称“通用并发摘要认证完成”。

### 5.3 合理的第一块实现范围

选择固定有限线程、SC、标量/明确 byte cells、已支持 mutex 和无递归的一个程序片段。
候选来源可以是 AI 或 BMC/path-focusing；认证接口独立于候选生成方法。
先证明一个关系摘要为何在全部相关环境写下保持，再探索更多性质。

“增加 verifier 就全项目 sound”仍不成立：trusted frontend、对象/数值翻译、环境 over-approx 和 API 合同都是可信边界。
应把这些边界写进定理和工具配置。

## 6. 已有研究与潜在论文贡献

### 6.1 直接相关 prior art 已核实

David Monniaux、Laure Gonnord，
[Using Bounded Model Checking to Focus Fixpoint Iterations](https://www-verimag.imag.fr/~monniaux/biblio/Monniaux_Gonnord_SAS2011.pdf)，
SAS 2011，DOI `10.1007/978-3-642-23702-7_27`。

论文 §3.1–3.2 用 SMT 找从抽象集合出发、到达当前不变式之外的路径，再沿路径做抽象转移；
§3.4 的归纳性/终止建立在完整 reduced CFG 与覆盖循环的切点上，§4 讨论 narrowing 等扩展。
所以“BMC 反向帮助 AI”**已是至少 2011 年存在的思路**。
普通限定 bound 的竞争不存在，与其完整切点归纳证明不是同一件事。

并发依据：Miné LMCS 2012 的 interference fixpoint；
Goblint SAS 2021 的 side-effecting constraints 与 privatization；
Goblint ESOP 2023 的 local traces、关系 clusters、创建身份与 MHP。
顺序 path focusing 的定理不能在加入未经建模的环境变化后直接沿用。
原文及查阅范围见[publications.json](artifacts/ai-audit-2026-10-10/publications.json)。

后续补充核对了 STTT 2024 的 digest framework 与 VMCAI 2026 的
Data Race Detection by Digest-Driven Abstract Interpretation。
它们已经研究了可调并发敏感性、摘要可接受性及访问不并行谓词的组合；
这些不能再当作本项目独有贡献。具体与 IKOS 的差异及参考驱动 TN 流程见
[优化计划 §8](ikos-ai-optimization-plan-2026-10-10.md#goblint-tn)。
此补充采用作者扩展版，论文实验未在本轮复现。

### 6.2 值得检验的研究问题

一个具体题目方向：**面向线程模块化数据竞争分析的证书化双向抽象—符号反馈**。
这只是工作题名，不代表已证新颖性。

可能有价值的组合是：

1. AI 提供有上下文/版本的 may 值与对象信息、MUST 保护/动态身份事实，减少 BMC 查询规模。
2. 符号查询返回两类分开的结果：真实有限竞争执行，以及基于 AI 覆盖的候选排除/归纳闭包证书。
3. 失败模型仅指导 partition/packing/干扰分区；精化结果重新收敛或经归纳认证后才用于 SAFE。
4. 两个方向共享有类型的合同和失效机制，明确 heap byte overlap、动态实例与保护条件。
5. 按需查询证明实际减少总成本，而不是叠加两个昂贵分析器。

这里的“证书化”首先意味着可重查公式、依赖和合同，不应声称已经产生 solver proof object 或官方 witness。
若要缩小 SMT trusted base，再评估 proof-producing solver 与检查成本；不作为原型先决需求。

可能的论文贡献需实际回答：

- 并发环境干扰下，反馈排除/归纳保持性是否有新的、清楚的定理？
- 动态身份、字节对象与保护前提的合同管理，是否解决了现有方法未解决的集成问题？
- 相比只用 AI、只用 BMC、已有 AI→BMC，双向反馈是否带来 TN/可靠 TP 与时间/内存的共同收益？

目前不能断言答案都是肯定。还需系统检索 CEGAR、SMT-guided AI、thread-modular refinement、
interference pruning 和验证器组合的后续研究；若现有工具已做同样机制，应调整主张或转成工程贡献。
把 IKOS 与 Dartagnan 拼接、或者仅用 solver 判断区间表达式，不足以单独宣称方法创新。

## 7. 原型实验：怎样判断它值得继续

### 7.1 前提与分组

先完成审查 P0，固定提交、二进制、任务 manifest、机器模型、时限和资源。
当前冻结 1029 ILP32 回归集可以用于配对；2027 官方全集和规则未固定，不混称比赛最终结果。
最小反例补充双位宽覆盖，动态入口/无效 API 支路按支持范围记录。

至少比较：

| 配置 | 目的 |
| --- | --- |
| 正确性修复后的 AI only | SAFE 基线与候选成本 |
| 当前 AI→BMC | 已有 TP 恢复/时间成本 |
| AI→BMC + 方案 A | 候选排除的 TN 与查询开销 |
| 再加方案 B | 引导精化是否优于固定 packing/partition 参数 |
| 可选方案 C 原型 | 认证增加的证明能力与额外成本 |
| 固定 Goblint/Dartagnan | 对应支持语义下的精度/速度参照；不把 Unsound/PASS/UNKNOWN 混成真值 |

方案 A 成果属于 solver-aided AI；
与优化计划§9.25–26已实现的原生地址排除比较时，需保留同一候选集合和事实前提，单独测量查询的新增收益与成本。
若论文强调 **BMC 本身的反馈**，还须证明方案 B/C 中存在 BMC/path-model 指导的因果收益。
只增加第二个 UNSAT 查询并不能自动证明双向 BMC 架构创新。

### 7.2 必须保存的结果

- 每任务判定变化、误报/漏报正反对照、独立接受的所选竞争执行。
- TN 恢复具体靠哪个排除/摘要，公式、事实来源、版本、定义性与覆盖前提。
- 总 CPU/墙钟/峰值内存、AI 重分析与迭代次数、候选/路径/事件数、SMT 构建与求解时间。
- 成功/失败/超时的反馈查询数，以及失败时 fallback 是否改变基线覆盖。
- 固定 packing vs 模型引导、使用/关闭证书、强/弱事实的消融。

性能主张要给配对中位数/分位数、超时和内存，而非只给一个总用时。
共享求解预算、并行度与 Java/C++ 启动成本处理要一致。
重复运行用于确认噪声；不为了结果重复调参到某组文件。

### 7.3 反例护栏

将本审查六类 FN 及旧 BMC 正确性反例纳入实验：
不同字段锁、transitive publication、未知入口、读时新干扰、多写 join、模糊句柄、
同入口多实例、共享 load guard、混合 width、整数 wrap、过期摘要。

尤其检验：错误 A 若被当成可信 bound 会产生假 UNSAT；
失效/未知必须让排除失效，而不是继续保留 SAFE。
“冻结集 FP/FN 为零”测不出 racy 标签文件上的假模型，仍需分别检查 FALSE 执行和 SAFE 覆盖。
