# BMC 后续实施方案：以具体差异用例验证并迁移参考语义

> 2026-10-09。本文是实施方案，不是已经实现的能力或 soundness 证明。
> 配对复现、源码阅读范围及版本指纹见
> [材料目录](artifacts/bmc-reference-guided-2026-10-09/manifest.json)。

## 1. 方法与优先级

采用“IKOS UNKNOWN、参考工具确认竞争”的具体任务驱动能力扩展：
先从 C 语义推导真实反例及关键约束，再观察固定版本 Dartagnan 的处理过程，
定位 IKOS 缺失的通用语义，最后在 IKOS 的现有层次中实现并验证。

不把完整通用反例框架的完成作为所有精度工作的前置条件。
每个能力增量同时补齐它需要的实例、取值、同步和反例证据；
现有 35 TP 的严格验证缺口继续单独跟踪，不能借新能力宣称全部解决。
当前 GraphML ACCEPT 不能严格绑定原 SMT 模型，限制见
[见证验证报告](ikos-bmc-witness-validation-2026-10-09.md)。

Dartagnan 源码、论文、阶段输出和标签都是需检验的证据。
一个用例的结果符合预测，只说明该用例观察一致；
语义迁移还需要前提论证、安全对照、变体及独立执行检查。
两工具可以选择不同合法反例，不要求模型、时钟或中间表达式逐字相同。

## 2. 首个已复现的差异任务

`c/goblint-regression/10-synch_02-thread_nonunique.yml`：ILP32，no-data-race。
main 循环创建 10 个 `t_fun` 实例，再逐一 join；每个实例执行
`myglobal = 42`。单个写语句的不同动态实例可以互相竞争。

本轮同输入重新运行：

- IKOS：一个未确认候选；两端入口均为 `t_fun`，
  `thread_activation_unproven=1`，尚未进入两路径展开或 SMT 查询。
  demote 模式的比赛结论为 UNKNOWN；诊断终端仍显示潜在 UNSAFE。
- Dartagnan：运行 JAR 为 4.3.1 / `7caef5c850dc2dbf81c5554dcf41e402007f7a19`；
  日志记录 11 个线程（含 main），最终 `FAIL / SVCOMP data race found`。
- 本轮读取了固定源码的 `ThreadCreation.createThreads`、
  `ProgramEncoder` 的线程激活/控制流、`LoopUnrolling` 和
  `PropertyEncoder.encodeDataRaces` 相关部分。
  尚未运行逐事件/模型探针或精确重放，不能断言选中了哪两个实例。

`ThreadCreation.createThreads` 为每个经处理的 `DynamicThreadCreate` 创建
独立 Thread，保留 creator 并绑定 TId；`ProgramEncoder` 把子线程执行与
创建执行/成功条件关联。这是首轮迁移的主要机制线索。
日志同时显示 `Program unrolled 1 times` 和 11 个线程，
因此不能仅凭全局 bound 数字推断 C 创建循环只执行了一次：
必须观察 Clang/LLVM、处理前后 IR 和实际创建事件。

待检验的语义预测如下，尚非逐阶段实测结论：

| 阶段 | 应建立的事实 | 检查方式 |
| --- | --- | --- |
| 前端/处理 | 每次动态创建及子线程的独立身份；还原创建循环在哪一层展开 | 保存 LLVM 与处理前后 IR、source/call/iteration 映射 |
| 创建可达性 | i=0、i=1 的创建可按真实条件执行，并存在成功创建分支 | 记录 guard、返回值、creator 与子线程 execution |
| 地址/取值 | 两个 worker 对同一个 global 的同范围写，值均为 42 | 记录 object、offset、width、值和局部变量实例 |
| 同步 | create 排序不自动排序两兄弟线程；之后的 join 不消除此前竞争 | 检查实际同步关系及完整路径 |
| 性质查询 | 至少有一对不同实例的写可以构成真实竞争，最终 SAT/FAIL | 导出所选访问对和可复核模型 |

IKOS 可以先构造 main 前两次创建的真实前缀，并暂停 main，调度两 worker 写入。
这不要求所有 10 个线程先建模，也不要求伪造从创建循环退出。
是否能省略其他步骤取决于这条具体执行能否扩展、性质是否已在该前缀成立。
不足的展开界只能留下 UNKNOWN，不能证明无界 SAFE。

## 3. 每轮实施流程

1. **固定差异。** 保留 task/YAML/input hash、机器模型、性质、内存模型、
   命令、边界、资源限制及两端二进制指纹。旧列表只用于筛选，必须重新配对。
   Dartagnan 的入口、CAT、失败/进展和初始化配置要核对；不同配置不强求等价。
2. **先写语义预测。** 从 C 推导一条合法有限反例，列明创建、局部值、共享读来源、
   地址范围、同步及必要其他线程。阶段检查围绕这些不变量，不能事后改预测迎合输出。
3. **观察参考实现。** 先用已有 IR/log/model 导出；缺少时在固定源码的隔离构建中加
   开关控制的探针。记录事件/线程对应、候选关系、关键约束和实际 SAT 模型。
   保留无探针构建，确认性质/结果没有被探针改变；不覆盖本地比赛工具包。
4. **定位差异归属。** IKOS 可能在抽象解释、候选过滤、展开、编码或输出层停止；
   被上游删除的候选不能靠 SMT 修复。比较语义事实，保留 C→LLVM→AR 的一对多映射。
5. **实现一个完整通用增量。** 写明前提、近似方向、证据和失败回退；
   参考算法的依赖要一并实现或证明不需要。先试该能力，遇到新前提就继续 UNKNOWN。
6. **验证泛化与反例。** 同入口两个实例必须独立；加入只有一个创建、互斥分支创建、
   公共锁、逐次 create/join 等安全对照；再测改名、helper、控制流及循环变体。
   真实执行验证与同工具输出对比是不同证据，均须注明覆盖范围。
7. **冻结集配对验收。** 构建同步 install，双架构 P0 与相关回归，然后 2026 全量 A/B。
   记录逐任务转移、FP/FN、UNKNOWN、错误/超时和资源变化。
   有新 FP/FN 时先处理正确性；不能用 TP 净增抵消。

具体阶段并非每层各有一个独立 SAT/UNSAT 结论。
部分编码的 SAT 不能证明竞争；以完整执行约束和性质查询作为最终判据。

## 4. IKOS/C++ 落点与协同

| 所属层 | 本轮关注点 | 迁移边界 |
| --- | --- | --- |
| checker / CandidateFacts | 保留 AI 的 may-create、may-alias、offset 和候选来源 | may 信息辅助筛选，不能证明某实例执行；过滤须保持性 |
| unroll / 创建前缀 | 有界循环状态、调用上下文、动态创建及变量定义身份 | 函数名、创建源码行和 `ar::Statement*` 均不足以唯一标识动态实例 |
| encode | 创建条件/成功分支、实例局部值、具体对象、取值和同步 | 复用已有机器整数及 SC 供值能力，不引入无来源的自由 load |
| 反例/输出 | 所选动态实例与步骤、创建依赖和实际值 | 延伸现有记录，checker 与 witness 消费相同证据 |

首先读取 `two_live_threads` / `conditional_live_threads` 和实际创建前缀的调用链，
再决定循环实例应在哪一层落地；不直接删除 `thread_activation_unproven`。
动态标识至少能区分父线程实例、创建位置及调用/迭代实例；
同一个静态语句的多次执行必须有不同事件和局部定义身份。

复用 `CandidateFacts`、`BmcEvent`、已有展开和取值机制。
有多个消费者且确有需要时再拆独立类型或实现文件；
不预先建立一般 CAT 引擎、通用框架或第二套内存分析器。
线程/内存执行语义与 race 性质查询保持分离，以便后续其他性质复用。
若直接复制参考源码而非重写算法，核对并保留适用许可和归属要求。

IKOS 事实贡献必须通过消融确认：开/关某项事实后保持同一语义和查询边界，
比较候选/依赖规模、时间、内存及结果。共享读区间的 sound 契约未建立前，
不把它作为实际读值的约束。只观察消费次数不能证明架构收益。

## 5. 后续顺序和交付

首轮聚焦循环中的同入口动态创建；通过后优先覆盖同机制任务，
再按最新重叠阻塞原因选择 join 数组句柄、main 单次 allocation 的对象身份、
必要第三线程/共享值依赖等具体差异。不能提前承诺解除一个 gate 就恢复整桶任务。

每轮交付：最小正反例、事先预测/实际观察对照、固定参考源码依据、
IKOS 通用补丁、反例证据、针对性与全量验证、遗留前提。
既检查选中的具体反例，也检查新增规则是否会误删候选或错误证明 SAFE。

## 6. Skill 一致性与能力边界

核对安装和仓库中的 `ikos-conc-semantics`：本方案符合其
“Read the original paper/specification and versioned reference implementation”
和“Do not import Dartagnan's conclusions while omitting its supporting encoding”。
也符合最小通用修改、禁止文件名/标签特判、保守回退和配对验证要求。
`ponytail` 要求最小完整改动、复用已有能力及非平凡逻辑的验证；本方案不冲突。
本轮不需要修改 skill 或新增强制审批流程。

这些工程步骤可以自行推进；单用例差分不能替代普遍 soundness 证明，
也不能保证精度收益。模型重放验证受支持子集，不能自动证明前端语义保持。
官方 2027 配置需官方确认；论文级全系统正确性主张仍需独立专业复核。
