## 3. Ubuntu 依赖与 adapter 文件清单不同

`required_ubuntu_packages` 安装系统软件包；`program_files()`/`REQUIRED_PATHS` 描述工具自身需要搬运的文件。后者不安装软件包，也不需要枚举整个 `/usr/lib`。

实际核对了 BenchExec 当前 main：

| adapter | 自带路径清单 | executable 定位 |
|---|---|---|
| [CPAchecker](https://github.com/sosy-lab/benchexec/blob/main/benchexec/tools/cpachecker.py) | 明确列 bin、JAR、native libs、scripts/config；按 executable 父目录解释 | `subdir="bin"`，另有 scripts fallback |
| [Goblint](https://github.com/sosy-lab/benchexec/blob/main/benchexec/tools/goblint.py) | 没有额外 REQUIRED_PATHS | 查 runner，再查 goblint |
| [ESBMC](https://github.com/sosy-lab/benchexec/blob/main/benchexec/tools/esbmc.py) | 没有额外 REQUIRED_PATHS | 查 wrapper |

因此，“必须列出所有依赖否则不能参赛”是不准确的。IKOS 当前清单只有入口，在需要按 `program_files()` 搬运时不足；在完整 FM-Tools 容器内运行不必因为这一点就认定失败。自带 bin/libexec/lib/llvm/include 的声明是部署改进建议，不是额外复制 Ubuntu 系统库的要求。

本轮保留现有库部署：glibc/GMP/Boost 等由声明的 Ubuntu 包提供；APRON、LLVM 工具/库及匹配构建版本的 Z3 已由原打包脚本自带。Z3 同时列系统包并有自带版本是已有配置，清理重复依赖前应核对 ABI 和干净容器行为。没有因为文件清单建议而增加一套新的系统库。

本轮未修改 BenchExec adapter 或远端 PR。原报告里“归档根目录找不到 bin/ikos”仍是可复现的定位限制；是否由 FM 容器 PATH 避开，应以实际集成运行核对。
